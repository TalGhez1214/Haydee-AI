JOB 1

Ingest Automatic

Triggered by manuscript/uploaded

For each chapter in the manuscript, Claude receives the full chapter text and performs a deep structural analysis. All chapters are processed sequentially. Everything is saved when all chapters are done.

Per-chapter: What Claude extracts

  • Characters — name, name variants, role (protagonist / secondary / minor / narrator), first appearance quote
  • Glossary candidates — source-language terms that need translation decisions, with type and frequency
  • Culture flags — culturally non-portable passages with severity level (high / medium / low) and 2–3 adaptation approaches
  • Untranslatable passages — wordplay, puns, dialect, form-dependent text — with strategies for the translator
  • Chapter summary — 1–3 sentence description of what happens in the chapter New

After all chapters: What gets saved

  • Characters deduplicated by name → characters
  • Glossary terms deduplicated by source term → glossary_terms (status: pending)
  • Culture + untranslatable flags → flags
  • Character names found per chapter → chunks.character_mentions
  • Chapter summary saved per chunk → chunks.summary New
  • Denormalized cache rebuilt → project_memory
  • High-priority to-dos auto-generated → project_todos

character/refresh-profile — one event per detected character → triggers Job 2

JOB 2

Character Profile Automatic

Triggered by character/refresh-profile — runs once per detected character (in parallel)
  • Loads all chunks where chunks.character_mentions contains this character
  • Extracts sentences mentioning the character using regex pattern matching
  • If fewer than 5 passages found → skips (not enough evidence)
  • Claude reads all passages and generates exactly 3 tone descriptors — each with a supporting quote from the text (e.g. "cold and formal", "self-deprecating", "commanding")
  • Saves tone tags to characters.tone_tags
  • Updates project_memory with the new tone profile
Used for: Translation prompt (character voice), assistant context, consistency checks
JOB 7

Build Knowledge Base New Automatic

Triggered by manuscript/ingested — runs once per manuscript upload
  • Loads all chunks for the manuscript from chunks
  • For each chunk, picks the best text input: chunks.summary if available (preferred — semantically dense), otherwise the first 4,000 characters of the full chapter text
  • Sends text to Voyage AI REST API (voyage-3-lite model) in batches of 64
  • Voyage AI returns a 512-dimensional float vector for each text — a mathematical representation of the chapter's meaning
  • Stores each vector in chunks.embedding (pgvector column)
  • Logs API usage to ai_call_log with job_type: 'embeddings'
Result: The book is now "searchable by meaning" — any natural language question can be matched to the most relevant chapters

On-Demand Jobs — triggered by the translator
JOB 3

Culture Flags On-demand

User triggers a culture re-scan on a specific chapter.

  • Sends full chapter text to Claude
  • Finds culturally embedded passages that may not survive translation (food, customs, humour, social codes)
  • Each flag has severity and 2–3 adaptation approaches
  • Saves to flags (type: culture)
JOB 4

Consistency Check On-demand

Translator submits a chapter draft for review.

  • Loads the translator's working translation draft
  • Loads all confirmed character names and approved glossary terms from project_memory
  • Claude finds deviations: wrong character name, unapproved term translation
  • Saves to flags (type: consistency)
JOB 5

Untranslatable Scan On-demand

User requests a deeper scan of a chapter for form-dependent language.

  • Sends chapter text to Claude with instructions to find passages where form matters
  • Finds wordplay, puns, dialect, sound patterns, alliteration, acrostics
  • Each passage gets 2–4 concrete translation strategies
  • Saves to flags (type: untranslatable, severity: high)
JOB 6

Translation On-demand

Translator highlights text in the manuscript and clicks "AI translate".

  • Looks up approved glossary terms that appear in the selection
  • Loads character profiles for characters named in the selection
  • Fetches summaries of the current chapter + its neighbours (N−1, N, N+1) from chunks.summary for narrative context New
  • Claude produces a single high-quality translation using all this context
  • Result stored in translation_requests, polled by the UI
How the Knowledge Base Powers the AI Assistant
RAG Assistant New

Answering any question about the book

When the translator asks a question in the chat panel, the system builds a rich context before calling Claude:

  • Semantic search — the question is embedded with Voyage AI, then pgvector finds the 4 most relevant chapter summaries using cosine similarity on chunks.embedding
  • Chapter pinning — if the translator is on the manuscript view, the current chapter and its neighbours are always included regardless of semantic rank
  • Characters — all character profiles (role, tone tags, confirmed target name, translator notes) are appended to the context
  • Approved glossary — all approved term translations are included so Claude gives consistent answers
  • Claude receives this full context in the system prompt and streams its response back in real time
Example questions now answerable: "How does the protagonist's voice change from chapter 1 to chapter 12?" · "Should I translate this cultural reference literally or adapt it?" · "What does the narrator's tone tell us about their relationship to the story?"
Context Flow

What Claude sees for every request

Every AI call is assembled from the same layered context stack:

① Chapter Summaries (RAG) ✨ New
The 3–5 most semantically relevant chapters to the current query, fetched via vector similarity search
② Character Profiles
All characters with confirmed target names, tone tags, and translator notes
③ Approved Glossary
All terms the translator has approved with their exact target-language translations
④ Project Metadata
Title, author, source → target language pair, genre, style guide
⑤ Conversation History
Last 10 messages from the current session for continuity

All AI jobs run as background workers via Inngest — they never block the HTTP response. The translator can keep working while processing happens.

Every Anthropic and Voyage AI call is logged in ai_call_log with token counts and cost in USD.
